# Phase 4B device setup

## Isolated LAN API

Use a private Windows IPv4 address reachable from the iPhone on the same trusted Wi-Fi. On the emulator, use that address or use `10.0.2.2` for the Windows loopback listener. Android and iOS both require a valid certificate with the API address in its Subject Alternative Name. A publicly trusted certificate and private DNS name also work through standard device trust.

From the repository root, start the isolated MongoDB project.

```powershell
$env:PARKFAIR_MONGO_PORT = '27149'
docker compose -p parkfair-phase4b -f infrastructure/compose.dev.yml up -d --wait
```

Create a disposable certificate chain in a temp directory. Use the API IP as `$apiAddress`. For emulator-only testing with `10.0.2.2`, set `$bindAddress` to `127.0.0.1`. For both devices, use the private LAN IP for both. Git for Windows bundles OpenSSL at the path shown below.

```powershell
$apiAddress = '<private LAN IP>'
$bindAddress = $apiAddress
$tls = New-Item -ItemType Directory -Path (Join-Path $env:TEMP ('parkfair-tls-' + [guid]::NewGuid()))
$openssl = 'C:\Program Files\Git\usr\bin\openssl.exe'
Push-Location $tls.FullName
& $openssl req -x509 -newkey rsa:2048 -nodes -days 7 -subj '/CN=ParkFair local QA CA' -keyout root.key -out root.pem -addext 'basicConstraints=critical,CA:TRUE' -addext 'keyUsage=critical,keyCertSign,cRLSign'
& $openssl req -new -newkey rsa:2048 -nodes -subj "/CN=$apiAddress" -keyout leaf.key -out leaf.csr
@("subjectAltName=IP:$apiAddress",'basicConstraints=critical,CA:FALSE','extendedKeyUsage=serverAuth') | Set-Content leaf.ext -Encoding ascii
& $openssl x509 -req -in leaf.csr -CA root.pem -CAkey root.key -CAcreateserial -days 7 -extfile leaf.ext -out leaf.pem
& $openssl verify -CAfile root.pem leaf.pem
& $openssl x509 -in root.pem -outform DER -out ParkFair-QA.cer
Pop-Location
node backend/scripts/mobile-dev.js $bindAddress "$($tls.FullName)\leaf.key" "$($tls.FullName)\leaf.pem"
```

The process prints one temporary password for three synthetic accounts. It creates a new randomly named database on the loopback replica set and keeps external sending disabled. The server binds only the chosen private address. If Windows Firewall blocks the iPhone, an owner-approved private-network rule scoped to the phone and port 5443 is needed.

For repeatable host-side qualification, generate the same chain for `127.0.0.1` and leave port 5443 available. From the repository root run:

```powershell
$env:NODE_EXTRA_CA_CERTS = "$($tls.FullName)\root.pem"
node backend/scripts/verify-mobile-dev.cjs $tls.FullName
Remove-Item Env:NODE_EXTRA_CA_CERTS
```

This checks certificate validation, native auth headers, mapped CSV, correction and coverage, approval, publication, manual activation, resident current and upcoming reads, empty history, refresh rotation and logout over HTTPS.

For iPhone testing with the private CA, transfer only `ParkFair-QA.cer` privately. Install its profile under Settings → General → VPN & Device Management, then enable full trust under Settings → General → About → Certificate Trust Settings. Confirm the readiness response in Safari at `https://<address>:5443/api/health/ready` before signing in. Remove the profile when finished. Keep private keys outside the repository.

Set `EXPO_PUBLIC_API_URL=https://<address>:5443/api` in the ignored `mobile/.env.local` and restart Metro. Use EAS environment `preview` for the internal preview's public API URL. Staging uses its own fixture service and hostname. Production configuration is supplied separately when deployment is authorized.

## Android on Windows

Use the dependency versions generated by Expo SDK 58 and the project-scoped CMake path limit. For a private CA, set `PARKFAIR_DEBUG_TLS_CA` to the path to root.pem and `PARKFAIR_DEBUG_TLS_HOST` to the single API IP before prebuild. The opt-in generated manifest trusts the CA only for that address and only in debug APKs. Loopback access supports Metro.

```powershell
Set-Location E:\ParkFair\mobile
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$init = (Resolve-Path ..\docs\design\phase-4\short-objects.gradle).Path
npx expo prebuild --platform android --no-install
.\android\gradlew.bat -p android :app:assembleDebug '-PreactNativeArchitectures=x86_64' --max-workers=2 -I $init
$adb = "$env:ANDROID_HOME\platform-tools\adb.exe"
& $adb devices -l
& $adb shell getprop sys.boot_completed
& $adb install -r .\android\app\build\outputs\apk\debug\app-debug.apk
& $adb reverse tcp:8081 tcp:8081
npx expo start --dev-client --localhost
```

Launch the emulator after Gradle finishes. When changing CA settings, regenerate the ignored Android directory with `npx expo prebuild --clean --platform android --no-install` first. Keep the CA unset for normal platform trust and any EAS build.

## iPhone on Windows

Expo lists SDK 58 for the current iOS Expo Go. Use `npx expo start --go --lan` for a preliminary smoke test on the same Wi-Fi. SDK 58 targets iOS 16.4 or later. Use a signed development build for ParkFair-specific permissions, lifecycle and device qualification. Both EAS profiles use the existing `com.cube14.parkfair` identifier. SecureStore and system document picking are the native features in scope. Local-network permission supports development API and Metro access.

Ad hoc installation requires an active Apple Developer Program membership, typically US$99/year or the local equivalent. Expo's free tier currently lists 15 iOS and 15 Android builds with low-priority queuing. Check account quota before choosing paid capacity. [Apple enrollment](https://developer.apple.com/programs/enroll/) · [Expo pricing](https://expo.dev/pricing) · [Expo Go availability](https://expo.dev/go)

After the owner authorizes account use, source upload and signing, run the following from `E:\ParkFair\mobile`.

```powershell
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest device:create
npx eas-cli@latest build --platform ios --profile development
# For a standalone internal preview with the preview API URL configured in EAS:
npx eas-cli@latest build --platform ios --profile preview
```

Open the registration URL on the iPhone, install the registration profile, and select that device when EAS asks for ad hoc provisioning. Open the completed build link in Safari, install, and enable Developer Mode if iOS prompts. For the development build, start Metro using `npx expo start --dev-client --lan` and open the QR code from ParkFair. The internal preview includes its JavaScript bundle. [Expo internal distribution](https://docs.expo.dev/build/internal-distribution/) · [Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/)

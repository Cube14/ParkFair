# ParkFair Database Design

## 1. Database Overview

Database Type:
MongoDB

Purpose:
Store residents, flats, vehicles, parking allocations, allocation balances, notifications, and system configurations.

---

# 2. Collections

## Users

Purpose:
Authentication and authorization.

Schema:

```javascript
{
  _id: ObjectId,

  name: String,

  email: String,

  phone: String,

  passwordHash: String,

  role: String,

  isActive: Boolean,

  createdAt: Date,

  updatedAt: Date
}
```

Role Values:

* ADMIN
* RESIDENT

Indexes:

* email (unique)
* phone

---

## Flats

Purpose:
Represent residential units.

Schema:

```javascript
{
  _id: ObjectId,

  flatNumber: String,

  ownerName: String,

  residentUserId: ObjectId,

  isActive: Boolean,

  createdAt: Date,

  updatedAt: Date
}
```

Indexes:

* flatNumber (unique)

---

## Vehicles

Purpose:
Store resident vehicles.

Schema:

```javascript
{
  _id: ObjectId,

  flatId: ObjectId,

  vehicleNumber: String,

  vehicleType: String,

  isActive: Boolean,

  createdAt: Date,

  updatedAt: Date
}
```

Vehicle Types:

* CAR
* SUV
* BIKE
* OTHER

Indexes:

* vehicleNumber (unique)
* flatId

---

## Allocations

Purpose:
Store parking allocation records.

Schema:

```javascript
{
  _id: ObjectId,

  flatId: ObjectId,

  rotationNumber: Number,

  status: String,

  startDate: Date,

  endDate: Date,

  generatedBy: String,

  createdAt: Date
}
```

Status Values:

* INSIDE
* OUTSIDE

Generated By:

* SYSTEM
* ADMIN

Indexes:

* flatId
* rotationNumber
* startDate

---

## AllocationBalances

Purpose:
Track long-term fairness.

Schema:

```javascript
{
  _id: ObjectId,

  flatId: ObjectId,

  actualInsideDays: Number,

  expectedInsideDays: Number,

  balance: Number,

  lastUpdated: Date
}
```

Balance Formula:

balance = actualInsideDays - expectedInsideDays

Interpretation:

Positive:
Received extra inside parking.

Negative:
Deserves additional inside parking.

Zero:
Perfect fairness.

Indexes:

* flatId

---

## Notifications

Purpose:
Track all sent notifications.

Schema:

```javascript
{
  _id: ObjectId,

  userId: ObjectId,

  type: String,

  message: String,

  status: String,

  sentAt: Date
}
```

Notification Types:

* EMAIL
* WHATSAPP

Status Values:

* PENDING
* SENT
* FAILED

Indexes:

* userId
* sentAt

---

## Configurations

Purpose:
Store society-wide settings.

Schema:

```javascript
{
  _id: ObjectId,

  totalCoveredParking: Number,

  rotationDurationDays: Number,

  totalFlats: Number,

  notificationLeadTimeHours: Number,

  updatedAt: Date
}
```

Example:

```javascript
{
  totalCoveredParking: 8,

  rotationDurationDays: 10,

  totalFlats: 14,

  notificationLeadTimeHours: 24
}
```

---

## AuditLogs

Purpose:
Track all important actions.

Schema:

```javascript
{
  _id: ObjectId,

  userId: ObjectId,

  action: String,

  entityType: String,

  entityId: ObjectId,

  details: Object,

  timestamp: Date
}
```

Examples:

* Allocation Generated
* Resident Updated
* Vehicle Added
* Configuration Changed

Indexes:

* userId
* timestamp

# 4. Data Retention Policy

Allocations:
Permanent

Balances:
Permanent

Audit Logs:
Permanent

Notifications:
Minimum 1 year

Configurations:
Permanent
